# dashboard.md — Guardrails for agent-generated pages

You are an agent (travel-agent, trainer, builder, wedding-planner, etc.) creating a page for Harry's dashboard. This document is the contract you must follow. The framework is designed so that following these rules = a working page that ships safely. Breaking them = a CI failure that blocks your push.

## What you're allowed to do

1. Create exactly one new file under `src/pages/generated/<slug>.tsx`
2. Append exactly one entry to `src/pages/generated/registry.ts`
3. Use **only** components imported from `'../../components/generated'`
4. Use **only** these things from MUI: `Box`, `Grid`, `Stack`. (For everything else, compose with the generated building blocks.)

That's it. If you find yourself wanting more — stop and ask Harry. The constraint is the feature.

## What you must NOT do

- ❌ Import from `@supabase/supabase-js`, `axios`, or `fetch` anything
- ❌ Use `useState`, `useEffect`, `useRef`, or any other hook
- ❌ Import from `../components/home`, `../components/common`, `../hooks`, `../lib` (those are reserved for the main dashboard)
- ❌ Edit any file outside `src/pages/generated/` and `src/pages/generated/registry.ts`
- ❌ Add new dependencies
- ❌ Use `dangerouslySetInnerHTML`
- ❌ Add `<script>` tags or third-party iframes (use `<MapEmbed>` if you need a map; it sandboxes iframes correctly)
- ❌ Reference `localStorage`, `sessionStorage`, `document`, `window`

If you need to *show* live data that exists in Supabase, encode the snapshot as a literal in the page at write-time. The page is a static artifact, not a live view. (If Harry actually needs a live page, he'll add it to the main dashboard manually — that's not your job.)

## Allowed building blocks (the full vocabulary)

All come from `'../../components/generated'`:

| Component       | When to use it |
|-----------------|----------------|
| `<PageHero>`    | Top of the page. Title, subtitle, optional banner image, accent color, tags |
| `<SectionHeader>` | Divider between sections — overline title + optional hint |
| `<InfoCard>`    | Generic card wrapper for arbitrary content |
| `<KeyValueGrid>` | Quick facts grid — { label, value }[] |
| `<BookingCard>` | Flight, hotel, rental, reservation, tour — full structured booking display |
| `<ItineraryDay>` | One column = one day. Time-stamped items with kind dots |
| `<BudgetCard>`  | Categorized spending breakdown w/ optional cap & progress bar |
| `<ChecklistCard>` | Task list with done/not-done checkmarks (display only) |
| `<LinkOut>`     | External link tile — emoji + label + hint + target=_blank |
| `<GalleryGrid>` | Image grid — 2/3/4 columns, optional captions, optional click-out |
| `<MapEmbed>`    | Place card with Google Maps deep link |
| `<TimelineList>` | Vertical timeline with done/current/upcoming statuses |
| `<StatTile>`    | Big number tile with label, hint, optional delta |
| `<QuoteBlock>`  | Pull quote, italic with attribution |
| `<TwoColumn>`   | Layout helper — primary/secondary split |

Read each component's prop types before using it. Don't pass props that aren't in the type definition — the build will fail.

## Page skeleton

```tsx
// Generated by: <your-agent-id>
// Created:      <YYYY-MM-DD>
// Slug:         <kebab-case-slug>

import React from 'react';
import { Box, Grid } from '@mui/material';
import {
  PageHero, SectionHeader, BookingCard, ItineraryDay, BudgetCard,
} from '../../components/generated';

const MyPage: React.FC = () => (
  <Box>
    <PageHero
      title="Trip to Positano"
      subtitle="5 days · July 2026"
      tags={['italy', 'honeymoon']}
      accent="#26A69A"
    />

    <SectionHeader title="Bookings" />
    <Grid container spacing={2.5}>
      <Grid size={{ xs: 12, md: 6 }}>
        <BookingCard kind="flight" title="JFK → NAP" /* ... */ />
      </Grid>
    </Grid>
  </Box>
);

export default MyPage;
```

## Registering your page

After creating `src/pages/generated/<slug>.tsx`, append one entry to `src/pages/generated/registry.ts`:

```ts
{
  slug: 'positano-2026-07',
  title: 'Positano · July 2026',
  emoji: '🇮🇹',
  kind: 'trip',                      // 'trip' | 'project' | 'report' | 'plan' | 'persona' | 'other'
  author: 'travel-agent',            // your agent id
  createdAt: '2026-05-03',           // today, ISO date
  summary: 'Honeymoon scouting — 5 days Amalfi Coast.',  // optional, ~80 chars
  component: React.lazy(() => import('./positano-2026-07')),
},
```

Keep the array alphabetically sorted by `slug`.

The page will appear in the sidebar under "Spaces" and at `/spaces/<slug>` automatically.

## Content rules

- Mobile-first. Use `Grid size={{ xs: 12, sm: 6, md: 4 }}` patterns. Test mentally at 320px wide.
- Use `accent` prop on PageHero to set the page's color identity. Trip pages = teal. Reports = amber. Project hubs = grey-blue. Personas = purple.
- Image URLs: prefer Unsplash, public CDNs, or hot-link from official sources you trust. **Do not** upload files. **Do not** reference local paths.
- Keep titles ≤ 60 chars. Body text ≤ 300 chars per element. The dashboard renders tight.
- Use `<QuoteBlock>` for one *opinionated* take (your voice as an agent). At most one per page.

## When to create a page (vs. an observation)

| Use a page when…                                  | Use `agent_observations` when…                |
|---------------------------------------------------|-----------------------------------------------|
| The artifact is a deliverable Harry will revisit  | The signal is a one-time alert or insight     |
| There are ≥ 5 distinct sections of content        | A single sentence captures it                 |
| Harry asked for a brief, plan, recap, or hub      | You spotted a pattern worth surfacing         |
| It will be referenced by URL                      | It belongs in the feed                        |

If you're unsure: pages are expensive; observations are cheap. Lean toward observations.

## Pre-push checklist

1. Page imports only from `../../components/generated` and `@mui/material` (limited subset)
2. No hooks, no fetching, no globals
3. Registry entry added, sorted by slug
4. `npx tsc --noEmit` exits 0
5. `npm run build` exits 0
6. `bash scripts/check-generated.sh` exits 0
7. Pushed to main; Netlify auto-deploys

## What happens if you break a rule?

The CI script `scripts/check-generated.sh` runs as part of the build and fails the deploy if:
- A file in `pages/generated/` imports from a forbidden module
- A file in `pages/generated/` calls a hook (regex match on `useState`/`useEffect`/etc.)
- The registry has a duplicate slug

Treat these as hard guards. Don't comment them out. If a guard is wrong, tell Harry and let him decide.
